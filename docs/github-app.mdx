title: GitHub App
description: Connect Longshore to GitHub with a least-privilege App, an encrypted secret store and verified webhooks.

Longshore talks to GitHub as a GitHub App. This page covers creating the App, where its credentials live, and how webhooks are verified. Longshore does not write to GitHub yet: checks come later.

## 1. Create a master key

The App's private key, webhook secret and client secret are kept in a built-in encrypted store. Each secret is sealed with AES-256-GCM under its own data key, and the data key is wrapped by a master key from a 32-byte file.

```sh
longshore keys init --file /secure/path/master.key
export LONGSHORE_MASTER_KEY_FILE=/secure/path/master.key
```

The file is created with mode `0600` and is never printed. Back it up: without it the stored secrets cannot be decrypted. A wrong or damaged key makes decryption fail closed. Each record binds the org id and secret name into its encryption, so a stored value cannot be moved to another name or org. No operation returns a secret value.

## 2. Create the App

```sh
longshore github-app create --url https://ci.example.com [--org my-github-org] [--name Longshore]
```

This serves a local page on `127.0.0.1` and prints its address. Open it, press the button, and approve the App on GitHub (under your account, or under `--org`). GitHub redirects back to the loopback callback with a one-time code, which Longshore exchanges for the App's credentials. They go straight into the encrypted store and are not printed.

The manifest asks for the least access that works:

| Permission | Level | Why |
| --- | --- | --- |
| Checks | write | Reporting results (used later) |
| Contents | read | Fetching the commit to run |
| Metadata | read | Listing repositories |
| Pull requests | read | Reading pull request facts |

Subscribed events are `push`, `pull_request` and `check_run`. GitHub also sends `installation` and `installation_repositories` to every App without a subscription.

The webhook URL is `<url>/api/v1/webhooks/github`. The `--longshore-org` flag chooses which Longshore org owns the App and its installations (default `local`).

Install the App on the repositories you want from the link the command prints.

## Installations, orgs and projects

When GitHub reports an installation, Longshore does not trust the payload. It re-fetches the installation and its repositories from the GitHub API with the App's own credentials, checks that the installation belongs to this App, and then maps it to the owning org and each repository to a project. A payload that names a different installation, account or repository than the API reports changes nothing. A repository already bound by another installation or org is left alone and reported. Removing a repository from an installation, or uninstalling the App, unbinds it.

## Webhook verification

The endpoint, `POST /api/v1/webhooks/github`, requires `LONGSHORE_MASTER_KEY_FILE`.

- The body is capped at 25 MiB (GitHub's maximum), by `Content-Length` and by the streamed size.
- The `X-Hub-Signature-256` HMAC-SHA256 is checked over the raw body with a constant-time compare, before anything is parsed. A bad signature gets `401` and stores nothing. Repeated failures from one client are rate limited (`429`).
- The delivery GUID is stored before the `202`. A delivery with a GUID seen before is acknowledged and not run again. Deliveries are kept for 30 days.
- Events with no handler are stored as ignored and acknowledged. A delivery interrupted before it finished is retried on the next start.
- Handlers are idempotent.

## Rotating the webhook secret

```sh
longshore github-app rotate-webhook-secret
```

A new secret is generated and set on the App through the GitHub API. The old one stays valid for 24 hours so in-flight deliveries still verify. If GitHub refuses the change, nothing changes locally.

## Installation tokens

Installation access tokens come from one function. It signs a short-lived App JWT, asks GitHub for a token scoped to the repositories and permissions of the call, and caches it until about five minutes before it expires. Tokens are never logged or returned by an operation.

## Other commands

`longshore github-app status` lists the App and its installations (no secrets).
